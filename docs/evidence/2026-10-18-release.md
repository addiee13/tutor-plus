# October 18 release validation

The release combines the reviewed Sprint 3 application changes with native date/time pickers. Every current date/time entry (booking start/end) uses the reusable `DateTimeField`. Labels explicitly state UTC, native controls handle date/time selection, and hidden ISO UTC values preserve the server contract. New date/time entry should use this component by default.

Executed against the current source and a production build, without an IDE:

- `npm run check`: typecheck, ESLint, Prettier and 110 unit tests passed.
- `npm run build`: production build passed, then served by `npm start -- --hostname 127.0.0.1 --port 3000`.
- `node --env-file=.env.local node_modules/vitest/vitest.mjs run tests/integration`: 10 passed, 2 session-boundary checks initially skipped. Running `tests/integration/session-boundary.test.ts` with `SUPABASE_TEST_SESSION_DB_MUTATIONS=true` passed both checks.
- Playwright with `.env.local`, `SUPABASE_TEST_SESSION_DB_MUTATIONS=true`, `PLAYWRIGHT_CHANNEL=chrome`, `PLAYWRIGHT_SKIP_WEBSERVER=1`, `PLAYWRIGHT_BASE_URL=http://127.0.0.1:3000`, configuration `tests/playwright.config.ts`, and `--workers=1`: 22 passed, 2 skipped. The two missing-environment tests intentionally require a separate unconfigured application; this run used real local Supabase.
- Booking tests ran in `America/New_York`, verified native input types and hidden UTC values, saved actual reservations, checked database timestamps, refreshed, cancelled, and verified cancellation persistence on desktop and phone. Screenshots in `screenshots/date-time-pickers/` were visually inspected.
- `sh supabase/tests/run-isolated.sh`: standalone DDL replay, Sprint 2/Sprint 3 SQL regressions and two-client booking concurrency passed in an isolated database. The original local database was preserved.
- Review subagent applied and recorded hosted migration `202610180003` and ran rollback-only hosted Sprint 2 and Sprint 3 regressions successfully. It closes planner edits at session end and prevents subjective assessment grading from compensating for missed objective answers.
- Published demo passwords were removed, rotated, and their sessions invalidated. The release is squashed onto main so the earlier credential-containing Sprint 3 commits are not introduced into main history.

Review also recovered an email-provider rate-limit fix from the separate linked worktree, updated the stale signup email-link test, and made historical demo seeding respect closed planners. No other required unique application change was identified in that worktree.

Untracked Sprint 3 report scripts, generated reports, and diagram drafts remain local. The report has unfinished handoff placeholders and unconfirmed external facts; it is not a validated submission.
